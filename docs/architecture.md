# Архитектура

JavaFX → сервисы Java → repositories JDBC → сервер PostgreSQL.

Сервером данных является PostgreSQL. Backend подключается к нему через JDBC.
В MVP сервисы работают в одном процессе с интерфейсом; HTTP API не используется.
Доступ к PostgreSQL должен быть ограничен доверенными рабочими местами.
Учётные данные БД доступны процессу приложения: сервисный слой не является
защитой от человека, который может менять программу или напрямую подключиться к БД.
Для недоверенных клиентов понадобится отдельный сервер backend.

## Таблицы

| Таблица | Назначение |
| --- | --- |
| roles | Роли admin/user |
| users | Учётные записи сотрудников, BCrypt и версия авторизации |
| authors | Авторы |
| genres | Жанры |
| publishers | Издательства |
| books | Библиографические записи |
| book_authors | Связь книг и авторов |
| book_copies | Физические экземпляры |
| readers | Читатели |
| reader_tickets | Читательские билеты |
| loan_statuses | Статусы active/returned |
| loans | Выдачи, даты и ставка штрафа |
| fines | Начисленные и оплаченные штрафы |
| settings | Срок выдачи и дневная ставка |

Пользователь приложения — сотрудник библиотеки. Читатель учитывается отдельно.
Просрочка вычисляется из planned_return_date, а не хранится отдельным статусом.

Выдача блокирует читателя, проверяет билет и задолженность, затем резервирует
пригодный экземпляр в транзакции. Уникальный частичный индекс запрещает две
активные выдачи одного экземпляра. Возврат и начисление штрафа атомарны.
История сохраняется: книги архивируются, читатели и пользователи отключаются.
