# Покрытие функций бэкенда

Интерфейс использует публичные сервисы `Backend`; SQL и бизнес-правила остаются в бэкенде.
Служебные методы подключения, проверки прав и валидации не требуют отдельных кнопок.

| Сервис и операции | Где доступны | Права |
| --- | --- | --- |
| `auth.login`, `logout`, `currentUser` | Вход, выход, проверка действительности сеанса при ошибке авторизации | Обе роли |
| `books.catalog` / `search`, `availableCopies` | Каталог: поиск по названию, ISBN, автору; страницы и доступность. `catalog` объединяет данные поиска и доступности | Обе роли |
| `books.get`, `findByIsbn`, `copies` | «По номеру / ISBN» и «Подробнее»: карточка книги, номер, описание, экземпляры | Обе роли |
| `books.create`, `update` | «Добавить книгу», «Редактировать книгу» в карточке | Администратор |
| `books.archive(..., true/false)` | «В архив» / «Восстановить» в карточке; архивная книга открывается по номеру | Администратор |
| `books.addCopy`, `setCopyCondition` | Карточка: «Добавить экземпляр», выбор экземпляра → «Состояние» | Администратор |
| `readers.search`, `get`, `tickets` | Читатели, выбор читателя для выдачи, карточка с билетами, имена в просрочках | Обе роли |
| `readers.create`, `update`, `setActive` | «Добавить читателя»; карточка → редактирование, отключение или активация | Администратор |
| `readers.issueTicket` | Карточка читателя → «Оформить / продлить билет» | Администратор |
| `loans.issue` | Каталог → выбрать книгу → «Выдать книгу» | Обе роли |
| `loans.entries`, `history`, `overdue`, `returnBook`, `returnBooks` | «Выдачи и возвраты», история читателей, «Вернуть выбранные книги» | Обе роли |
| `loans.statistics` | «Выдачи и возвраты» → «Статистика»: книги, экземпляры, читатели, выдачи, просрочки, сумма штрафов | Обе роли |
| `loans.statuses` | Названия статусов в таблице выдач загружаются из сервиса | Обе роли |
| `users.list`, `roles` | Сотрудники; доступные роли загружаются в формы создания и настройки доступа | Администратор |
| `users.create` | «Добавить сотрудника» | Администратор |
| `users.resetPassword` | Выбрать сотрудника → «Сбросить пароль» | Администратор |
| `users.setAccess` | Выбрать сотрудника → «Настроить доступ»: роль и активность | Администратор |
| `users.changeOwnPassword` | Настройки → «Изменить мой пароль» | Обе роли |
| `dictionaries.list` | Справочники и поля книги: авторы, жанры, издательства | Обе роли |
| `dictionaries.create`, `update`, `delete` | Справочники → добавление, изменение и удаление | Администратор |
| `settings.get`, `update` | Настройки → правила выдачи | Просмотр — обе роли; изменение — администратор |
| `fines.list`, `pay` | Штрафы выбранного читателя; «Отметить оплату» | Просмотр — обе роли; оплата — администратор |

## Ограничения существующего бэкенда

- Рабочий каталог и архив доступны через переключатель; книгу можно открыть по номеру записи или ISBN.
- Общие списки выдач и штрафов доступны для всей библиотеки либо выбранной группы читателей.
- Строки выдач и штрафов содержат название книги, читателя и инвентарный номер экземпляра.
- Пользователей можно отключать и включать, менять роль и пароль. Удаления и редактирования имени/логина API не предоставляет.
- Роли и статусы фиксированы; создание и редактирование их определений не предусмотрено.
- Списки сотрудников и справочников ограничены 500 записями.

Эти ограничения не обходятся прямым доступом к базе из фронта.

Регистрация расположена на экране входа и назначает роль сотрудника. «Состояние системы»
доступно администратору через `system.status`. На каждой странице есть справка «О странице».
Руководство по работе и защите проекта: [user-guide.md](user-guide.md).
