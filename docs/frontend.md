# Интерфейс JavaFX

## Запуск

JDK 21+, Maven 3.9+, PostgreSQL со схемой и первым администратором из README.
Соберите оба модуля: `mvn install -DskipTests`, затем `mvn -pl frontend javafx:run`.
В IDE запускайте `ru.library.frontend.Launcher` с classpath модуля `library-frontend`.
Переменные `LIBRARY_DB_*` задаются в конфигурации запуска; значения можно перенести
из локального `.env`, который Java автоматически не читает. Пароли сотрудников не сохраняются
интерфейсом, сеанс живёт только в памяти. `.env` содержит только подключение к БД.

## Экраны

- Вход: ошибки авторизации и подключения, повторный вход после окончания сеанса.
- Каталог: поиск названия/ISBN/автора, страницы по 12 записей, доступность, экземпляры,
  выдача выбранной книги. Администратор создаёт и редактирует книги, архивирует их,
  добавляет экземпляры и меняет их состояние. «По номеру» открывает любую книгу,
  включая архивную; администратор может восстановить её из карточки.
- Читатели: поиск контактов, карточка, билеты, история выдач и штрафы.
  Администратор добавляет и изменяет читателя, отключает его и выдаёт новый билет.
- Выдачи: общий список просрочек либо история конкретного читателя; подтверждение возврата.
  «Сводка» показывает статистику всей библиотеки, включая неоплаченные штрафы.
- Штрафы: начисления по выбранному читателю. Только администратор подтверждает оплату.
- Справочники: поиск авторов, жанров и издательств; изменение и удаление для администратора.
- Сотрудники: создание, роль, активность, сброс пароля. Только для администратора.
- Настройки: срок выдачи, ставка штрафа; изменение собственного пароля для обеих ролей.

Создание и изменение данных проходят через существующие сервисы `Backend`.
В модуле frontend нет SQL и обращения к repositories. Все блокирующие вызовы
выполняются в отдельном последовательном потоке. Чтение данных не блокирует окно
и навигацию; повторное сохранение блокируется только в отправляемой форме.
Разделы создаются один раз за сеанс и сохраняют поиск, страницу и выбранную строку.
После изменения данных другие разделы обновляются при открытии; данные старше минуты
также обновляются при переходе. Кнопка «Обновить» запрашивает данные текущего раздела.
При обновлении таблица сохраняет старые строки до ответа; запоздавшие ответы предыдущего
поиска игнорируются. Несохранённые настройки при переходах не перезаписываются.
JavaFX-контролы читаются и обновляются в потоке интерфейса.
При неудачном сохранении форма остаётся открытой с введёнными значениями.
Неверный текущий пароль не завершает действительный сеанс.

Минимальное окно — 1000×700. На небольшом экране таблицы прокручиваются,
а длинные значения доступны во всплывающей подсказке. Enter запускает поиск,
кнопки и формы доступны с клавиатуры, фокус имеет видимую рамку.
Строки с действиями имеют круглую отметку выбора слева: нажатие выбирает запись,
а явные кнопки под таблицей выполняют действие. Подпись рядом с кнопками показывает
выбранную запись. Наведение не окрашивает строку; справочные таблицы без действий
не поддерживают выбор. Открытие карточки выполняется кнопкой, без скрытого двойного клика.

## Границы текущего API

- Общего списка всех выдач нет: доступны просрочки и история читателя.
- Выдача содержит ID экземпляра без названия книги: в истории показан «Экземпляр № …».
- Поиск книг возвращает только неархивные записи. API списка архива отсутствует;
  архивная книга открывается через «По номеру». Номер указан в карточке и подтверждении
  архивирования. Восстановление использует существующий `archive(..., false)`.
- `books.catalog` возвращает книги, имена авторов и доступность за одно подключение
  и одну транзакцию, без отдельных запросов по каждой строке.
- Справочники и сотрудники ограничены backend до 500 записей. Ограничение указано в интерфейсе.
- Нет общего количества результатов поиска: пагинация запрашивает дополнительную запись,
  поэтому «Далее» отключается корректно и не показывает выдуманное число страниц.

Соответствие операций бэкенда интерфейсу описано в [frontend-coverage.md](frontend-coverage.md).
