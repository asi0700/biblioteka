# Локальный запуск в Windows

Для запуска нужны Java 21 или новее и работающий PostgreSQL. Настройка базы не устанавливает и не запускает сервер PostgreSQL.

## Сборка

Из корня проекта, используя Maven:

```shell
mvn install -DskipTests
mvn -pl frontend dependency:copy-dependencies -DincludeScope=runtime
```

Первая команда собирает и устанавливает модули в локальный кэш Maven. Вторая помещает библиотеки для запуска в `frontend/target/dependency`. После обновления исходников нужно повторить обе команды. Флаг `-DskipTests` пропускает тесты; проверки описаны в `testing.md`.

## Первая настройка базы

Запустите `setup-db.cmd` из корня проекта двойным щелчком либо командой `./setup-db.cmd` в терминале.

1. Укажите администратора PostgreSQL: обычно `postgres`, для него можно нажать Enter.
2. Введите пароль, заданный при установке PostgreSQL. Символы пароля не отображаются.
3. При создании первой учётной записи приложения укажите логин, имя и пароль длиной не менее 10 символов, затем повторите пароль.

По умолчанию настройка подключается к `localhost:5432`, создаёт базу `library`, отдельного пользователя PostgreSQL `library_app`, 14 таблиц и начальные справочники. Реквизиты подключения сохраняются в локальный `.env`, который исключён из Git. Пароль администратора PostgreSQL туда не записывается.

Если база уже существует и принадлежит другому пользователю или имеет другую структуру, настройка остановится. Для подключения к существующей базе заполните `.env` её реквизитами по инструкции в README. Данные из PostgreSQL другого участника не переносятся вместе с Git.

## Запуск приложения

Откройте `start.cmd`. Он читает `.env` и запускает приложение. Войдите с учётными данными приложения, созданными при настройке базы. Они отличаются от учётных данных PostgreSQL.

Повторная настройка перед каждым запуском не требуется. PostgreSQL работает как служба Windows. Если он недоступен, откройте «Службы», найдите службу PostgreSQL и запустите её. При автоматическом типе запуска служба включается вместе с Windows. Закрытие приложения не останавливает базу.

## Демонстрационные данные

После первой настройки запустите `load-demo.cmd`, затем нажмите «Обновить» в приложении. Команда загружает `database/demo-data.sql` через JDBC с реквизитами из `.env`. Добавляются 16 книг, 46 экземпляров, 8 читателей, выдачи и штрафы. Повторная загрузка не сбрасывает изменения и не восстанавливает исходное состояние. Сценарий показа описан в `demo.md`.

В DBeaver выберите подключение к базе `library`, откройте `database/demo-data.sql` и выполните весь SQL-скрипт в одном подключении, а не отдельную строку. Для выполнения нужен активный администратор приложения. Сам SQL-файл не является исполняемой программой Windows.

## Создание пользователей

На экране входа есть «Регистрация»: ФИО, логин, пароль (минимум 10 символов) и подтверждение. Backend назначает роль `user`. Выбрать себе административные права нельзя. Первоначальный администратор должен быть создан до регистрации.

Администратор также может открыть «Сотрудники» → «Добавить сотрудника», создать учётную запись и назначить роль. Роль «Сотрудник» соответствует `user`, роль «Администратор» — `admin`. Читатели добавляются отдельно в разделе «Читатели» и не являются учётными записями сотрудников.
