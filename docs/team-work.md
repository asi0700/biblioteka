# Работа участников

Основные ветки: backend-db, frontend, main.
В backend-db находятся backend и база данных; в frontend — интерфейс.
В main объединяются проверенные изменения.

## Первая публикация

Пока репозиторий пуст, локальная ветка backend-db не имеет коммитов.
После проверки файлов участник самостоятельно создаёт первый коммит и отправляет
ветку backend-db в origin с настройкой отслеживания.
Затем из проверенного коммита создаётся и отправляется main.
В настройках репозитория main выбирается основной веткой.
Автоматических коммитов и отправок в проекте нет.

Перед коммитом убедитесь, что .env, .local, target и настройки среды не попали
в список добавленных файлов. Не добавляйте пароли и данные рабочей БД.

## Второй участник

Второй участник получает репозиторий, переключается на main и создаёт ветку frontend.
Он добавляет отдельный модуль интерфейса и подключает library-backend.
Общий pom.xml, DTO и публичные методы сервисов меняются по согласованию участников.
Смена публичных методов должна сопровождаться обновлением docs/backend-api.md.

Перед объединением выполните проверку backend и сборку обоих модулей.
После отправки коммитов второй участник обновляет ветку из origin/main.
Локальные незакоммиченные изменения другого участника не передаются через GitHub.
